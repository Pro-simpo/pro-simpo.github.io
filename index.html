ShadowFactory – Red Team vs Blue Team

Cybersécurité · SOC · Cloud · R&D

ShadowFactory – Red Team vs Blue Team

Overview

Full-stack industrial cybersecurity simulation: a Red Team executes multi-phase attacks on a multi-VM environment simulating an industrial plant (IT + OT), while a Blue Team SOC built on Oracle Cloud Infrastructure (Wazuh, TheHive 5, Shuffle SOAR) monitors, detects and auto-responds in real time. The scenario reproduces the logic of Stuxnet on a small scale: a classic IT intrusion that ends with the silent manipulation of a simulated industrial controller.

My Role

  • Team project: I built the SOC side, and the attacks were played by the team
  • Deployment of the SOC stack on Oracle Cloud: Wazuh, TheHive 5 and Shuffle SOAR
  • Writing of the 15 custom Wazuh detection rules, which cover the 5 attack phases
  • Automated response workflow: Wazuh alert, Shuffle playbook, TheHive case and IP block with iptables, in under 5 seconds

Key Features

  • Full SOC stack on OCI: Wazuh SIEM, TheHive 5 case management, Shuffle SOAR automation
  • 6 virtual machines simulating IT (DVWA web server, Active Directory) and OT (PLC simulated with OpenPLC, Modbus TCP)
  • 5 attack phases: network scan, SQL injection and webshell, Active Directory brute force and Kerberoasting, SSH tunnel to the OT zone, PLC register manipulation over Modbus
  • 15 custom Wazuh detection rules mapped to each attack phase
  • Automated SOAR workflow: alert → IP block via iptables → incident case in TheHive
  • Three segmented network zones (IT, DMZ, OT/SCADA) using Oracle Cloud security lists
  • Red Team side: a network scanner written in Python by the team (port scan, Active Directory enumeration), validated against Nmap

Technologies

OCI Wazuh TheHive 5 Shuffle SOAR Modbus iptables Kali Linux Metasploit Python Active Directory

IDS/IPS Cloud Deployment on Azure

Cybersécurité · IDS/IPS · Azure

Déploiement d’un IDS/IPS dans le cloud Azure

Overview

Cloud-native intrusion detection and prevention system deployed on Microsoft Azure. Suricata 8.0.4 runs as an inline IPS engine within a custom VNet architecture, combining 50,000+ community signatures with 4 purpose-built detection rules for targeted threat coverage.

Key Features

  • Suricata 8.0.4 deployed on Azure VM in inline IPS mode (NFQUEUE)
  • Custom VNet with a public subnet (attacker VM) and a private subnet (Suricata and target VMs), and a route table sending the traffic through Suricata
  • NSG (Network Security Group) rules for cloud-layer traffic filtering
  • 50,000+ active Suricata ET Open signatures
  • 4 custom detection rules targeting specific threat patterns
  • Alert analysis from the Suricata EVE JSON logs with jq
  • Tested against simulated attacks: Nmap scans, ICMP flood (hping3), SSH brute force (Hydra) and LFI attempts (ffuf)

Technologies

Tracker solaire piloté par IA

Overview

Solar tracking system that orients a panel towards the sun in real time with LDR light sensors and a servomotor, and adds AI-based predictions. An ESP32 reads the sensors and sends the data to Firebase, an Arduino Uno drives the servomotor, and a Flutter mobile app shows live values, predictions and the panel charge.

Key Features

  • ESP32 (NodeMCU-32S) reading the LDR and DHT11 sensors, organised in FreeRTOS tasks
  • Arduino Uno driving the servomotor from the LDR values received over a serial link
  • Firebase real-time database for data synchronisation
  • Flutter mobile app with live data: power, harvested energy, charging time, light, temperature and humidity
  • Machine learning model that predicts upcoming values from the data history
  • Comparison screen between measured values and predictions, used to adjust the model

Technologies

Intelligent Parking System

FPGA · VHDL · Conception numérique

Système de parking intelligent

Overview

Parking management system on FPGA, written in VHDL and clocked at 50 MHz. It detects vehicles at the entry and exit, counts the free spaces in real time, shows the count on a 7-segment display and controls the access barrier automatically according to the state of the car park.

Key Features

  • Modular, hierarchical design in four blocks: space counter, barrier controller, 7-segment display driver and top-level module
  • Barrier controlled by a finite state machine: entry refused when the car park is full, exit always allowed
  • Safety rule: the barrier never closes while a vehicle is detected under it
  • Free spaces shown on a multiplexed 4-digit 7-segment display
  • Behaviour validated by testbench simulation before hardware implementation
  • Synthesis, place and route and programming with Quartus on a Cyclone IV FPGA, with infrared sensors and a servomotor

Technologies

VHDL FPGA FSM Quartus Cyclone IV

  • Nombre de places libres affiché sur un afficheur 7 segments multiplexé à 4 chiffres
